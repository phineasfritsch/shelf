# Shelfy - Final Build Spec (v1)

Single-user, self-hosted "one text box + expiring attachments" that stays live across a phone and a laptop. One Node process, one SQLite file, one volume, one container. This document is the implementation contract: build exactly this.

---

## 1. Decision summary

**Stack:** Node 24+ (ESM, `"type":"module"`; the image uses Node 26), `node:http` + `ws@8.21.3` for the WebSocket server, `node:sqlite` (`DatabaseSync`, WAL) for all metadata and the document log, `yjs@13.6.32` as the text CRDT on both server and browser, `node:crypto` scrypt for the password. No framework, no TypeScript, no bundler in the run or deploy path. The browser gets hand-written ESM modules served as-is plus one vendored `public/vendor/yjs.js` (produced once by `npm run vendor`, committed to the repo). Image: single-stage `node:26-alpine`, ~65 MB, cold start < 300 ms.

**The five decisions that matter, and why:**

1. **Yjs CRDT for the text box, not hand-rolled OT and never last-write-wins.** Every persona's dealbreaker is a lost keystroke, a cursor jump, or a stale tab clobbering newer text. With a CRDT those are properties of the data model: a reconnecting client sends only the ops the server lacks (state-vector diff), never its full text, so it *cannot* overwrite; concurrent inserts both survive. The server is a persist-and-relay; there is no transform code to get wrong. Cost: ~90 KB of vendored JS. The wire protocol is two binary tags + JSON control messages - `y-protocols`/`lib0` are *not* imported directly.
2. **Delta-walk textarea binding.** Remote changes are applied with `textarea.setRangeText()` per delta segment, and the caret/selection/scrollTop are shifted arithmetically - never `textarea.value = …`. Remote updates are queued while an IME composition is open (Gboard/iOS). Undo is a Yjs `UndoManager` tracking only local origins, so Ctrl+Z never undoes the other device.
3. **Zero build step.** `npm ci && node server.js` runs the whole thing. The only generated artefacts are `public/vendor/yjs.js`, `public/vendor/qrcode.js` (from a one-time `npm run vendor`, committed) and the PNG icons (`npm run icons`, committed). Docker copies `public/` verbatim; `esbuild` and `qrcode-generator` are devDependencies and never enter the image.
4. **Sessions that never expire in practice and are revocable per device.** DB-backed sessions (only `sha256(token)` stored), 365-day sliding lifetime, `HttpOnly; SameSite=Lax`, `Secure` auto-detected from TLS or `X-Forwarded-Proto` (fail-safe, works on `http://LAN-IP:8080` and behind Caddy with no config). Per-device list + revoke, "log out everywhere", and a QR "link this phone" flow so the password is typed on a phone keyboard at most once.
5. **Uploads are a single streaming raw-body `PUT` straight to disk; thumbnails are generated by the uploading device.** No multipart parser on the server, no chunk protocol (explicit non-goal), real byte progress via XHR, one-tap Retry that reuses the in-memory `File`. Thumbnails are ≤320 px JPEGs drawn on the client (the iPhone decodes its own HEIC), so the server has no image libraries. TTL sweeper unlinks bytes and deletes rows every 60 s; the download route enforces expiry itself; per-file Keep exempts from expiry.

**Explicitly rejected from the proposals:** chunked/resumable uploads, epoch/"compact history" UI, 30-day session rotation, persisted global login lockout (remote self-DoS), 10 s file-list polling, awareness cursors, `sha256` on files, `__Host-` cookie prefix, SW app-shell caching, two-column desktop layout, `POST /api/text-append`.

**Estimated size:** ~2,600 lines (server ~900, client ~950, CSS ~300, tests ~450). Suggested build order for one sitting: `config → db → auth → http/static/login → doc + ws → editor binding → files + sweeper → uploads UI + files view → history/sessions/QR → PWA/share → Docker → tests`.

## 3. Environment variables

All read once in `lib/config.js`, validated, effective config printed at boot with secrets redacted. Invalid values → exit 1 with a one-line reason.

| Var | Default | Meaning |
|---|---|---|
| `PORT` | `8080` | Listen port. |
| `HOST` | `0.0.0.0` | Listen address. |
| `DATA_DIR` | `/data` | The single persistent directory (SQLite + files + tmp + text mirror). Test-written at boot; if not writable: `DATA_DIR /data is not writable by uid <n>` and exit 1. |
| `PASSWORD_HASH` | - | Preferred. `scrypt$32768$8$1$<salt b64url 16B>$<key b64url 32B>` from `npm run hash-password`. |
| `PASSWORD_FILE` | - | Path (Docker/Compose secrets). Trimmed contents treated as `PASSWORD_HASH` if they start with `scrypt$`, else as `PASSWORD`. |
| `PASSWORD` | - | Plaintext convenience. Hashed in memory at boot with a fresh salt, then `delete process.env.PASSWORD`; logs `WARN auth: using plaintext PASSWORD, prefer PASSWORD_HASH`. |
| `SESSION_DAYS` | `365` | Sliding session lifetime. |
| `COOKIE_SECURE` | `auto` | `auto` = Secure when the request is HTTPS (TLS socket or `X-Forwarded-Proto: https`); `true`/`false` force. |
| `TRUST_PROXY` | `0` | `1` = trust `X-Forwarded-For` (rightmost entry = client IP) and `X-Forwarded-Host` from the immediate upstream. Does NOT gate `X-Forwarded-Proto` (see §4). |
| `ALLOWED_ORIGINS` | - | Comma-separated full origins accepted by the CSRF/WS Origin check in addition to the derived host (only needed when a proxy rewrites Host and you cannot set `TRUST_PROXY`). |
| `FILE_TTL_HOURS` | `168` | Default file lifetime (decimal allowed, e.g. `0.005` = 18 s for testing). `0` = files never expire by default. |
| `MAX_FILE_MB` | `2048` | Per-file upload cap (413). |
| `MAX_STORAGE_MB` | `0` | Total storage cap for files (507). `0` = unlimited. |
| `MAX_TEXT_KB` | `2048` | Client-enforced text box cap (server sends it in `hello`, logs a warning if exceeded). |
| `SWEEP_INTERVAL_SEC` | `60` | TTL sweeper cadence. |
| `LOGIN_MAX_FAILS` | `5` | Failures per IP within the window before 429. |
| `LOGIN_WINDOW_MIN` | `15` | Sliding window for the above. |
| `SHUTDOWN_TIMEOUT_SEC` | `20` | Max wait for in-flight uploads on SIGTERM. |
| `APP_NAME` | `Shelfy` | Title / manifest name. |
| `LOG_JSON` | `0` | `1` = JSON lines to stdout instead of text. |

**Password resolution order:** `PASSWORD_HASH` → `PASSWORD_FILE` → `PASSWORD` → `DATA_DIR/password.hash` → **first-run generation**.

**First-run behaviour (nothing configured, no `password.hash` on the volume):** generate a 20-character random password (`randomBytes(15).toString('base64url')`), scrypt-hash it, write the hash string to `DATA_DIR/password.hash` (mode 0600), and print once to stdout:

```
==================================================================
  No password configured. Generated one for you:

      <password>

  It is hashed at /data/password.hash and will be reused on
  restart. To choose your own: PASSWORD_HASH=$(npm run -s hash-password)
==================================================================
```

Env vars always override the file. There is never a hardcoded default password.

**Password change = automatic logout everywhere:** at boot compute `pwfp = sha256(hashString).slice(0,16)`; if `meta.pwfp` exists and differs, `DELETE FROM sessions` and log `auth: password changed, all sessions revoked`; then store the new `pwfp`.

## 4. Auth design

### Login page
`GET /login` serves `public/login.html` (302 → `/` if already authenticated). One `<form id="login">` containing `<input type="password" name="password" autocomplete="current-password" autofocus required enterkeyhint="go">` (font-size 16 px so iOS does not zoom), a show/hide toggle, one submit button, an inline error line. `login.js` intercepts submit and POSTs JSON; the real `<form>` + `autocomplete` is what makes iOS/Chrome password managers offer autofill. On 204 → `location.replace('/')`. 401 → "Wrong password". 429 → "Too many attempts - try again in N s" with a live countdown from `Retry-After`.

`GET /` serves `public/index.html` only with a valid session; otherwise 302 → `/login`. Because the server decides which HTML to send, an authenticated device never sees a login flash.

### Hashing
`crypto.scrypt(password, salt, 32, { N: 32768, r: 8, p: 1 })`, 16-byte random salt, string format `scrypt$32768$8$1$<salt b64url>$<key b64url>`. Verify: parse, scrypt with the stored params, `crypto.timingSafeEqual`. If parsing/length fails, still run scrypt against a dummy salt and compare against a dummy key so the timing path is identical. `scripts/hash-password.mjs` reads stdin (`docker run --rm -i shelfy node scripts/hash-password.mjs`), never argv.

### Sessions
`POST /api/login` body `{"password":"…"}` (JSON only, ≤ 4 KB; `Content-Type` must be `application/json`). Success: `token = randomBytes(32).toString('base64url')` (43 chars); insert `sessions(id_hash = sha256(token) hex, created_at, last_seen_at, ua)`; respond `204` with `Set-Cookie`. Failure: full scrypt cost, then `401 {"error":"bad_password"}`.

Lookup on every request and on WS upgrade: parse `sid` cookie → sha256 → `SELECT … WHERE id_hash=? AND last_seen_at > now - SESSION_DAYS*86400e3`. Sliding renewal: if `last_seen_at` is > 1 h old, update it and re-send `Set-Cookie` with a fresh `Max-Age` (the cookie's own expiry slides too). A device used at least once a year is never logged out. Server-set HttpOnly cookies are exempt from Safari ITP's 7-day cap. Expired rows pruned by the sweeper. No "remember me" checkbox - remembering is the only mode.

**Cookie, exactly:**
```
sid=<token>; Path=/; HttpOnly; SameSite=Lax; Max-Age=31536000[; Secure]
```
`Secure` is appended when `COOKIE_SECURE=true`, or when `COOKIE_SECURE=auto` and (`req.socket.encrypted` OR the first value of `X-Forwarded-Proto` is `https`). `X-Forwarded-Proto` is honoured **regardless of `TRUST_PROXY`**: spoofing it only makes the spoofer's own cookie Secure, so this is fail-safe, and it means plain `http://192.168.1.10:8080` gets a non-Secure cookie (no login loop) while Caddy/Traefik/nginx-with-`X-Forwarded-Proto` gets Secure with zero config. No `__Host-` prefix (it mandates Secure and would break LAN http). `SameSite=Lax`, not Strict, so a link to the app opened from another app arrives authenticated.

`isHttps(req)` (same rule) also decides the `ws:`/`wss:` scheme in the CSP header.

### Per-device management
- `GET /api/sessions` → `[{ "id":"<first 12 hex of id_hash>", "label":"iPhone · Safari", "createdAt", "lastSeenAt", "current":true }]`. Label derived from UA: device ∈ {iPhone, iPad, Android, Windows, Mac, Linux, Other} · browser ∈ {Safari, Chrome, Firefox, Edge, Other}.
- `DELETE /api/sessions/:id` → deletes rows whose `id_hash` starts with `:id` (12 hex, unique in practice), closes that session's WebSockets with `{t:"bye",reason:"revoked"}` + close code 4001.
- `POST /api/logout` → delete current row, `Set-Cookie: sid=; Path=/; HttpOnly; SameSite=Lax; Max-Age=0`, close its sockets. Client clears `localStorage` (`shelf.*`) before redirecting to `/login`.
- `POST /api/logout-all` → `DELETE FROM sessions`, close every socket (4001).

### QR "Link a phone"
- `POST /api/link` (authenticated) → `token = randomBytes(24).base64url`; insert `link_tokens(hash=sha256(token), expires_at=now+5min)`; prune expired; respond `{ "token":"…", "expiresAt":… }`. Client renders `${location.origin}/#link=${token}` as an SVG QR (`qrcode(0,'M')`, `addData`, `make`, `createSvgTag({cellSize:4, margin:2})`) with a 5-minute countdown and the URL in plain text.
- Phone scans → opens the URL → server 302s to `/login` (browsers preserve the fragment across redirects) → `login.js` sees `#link=`, `POST /api/link/claim {"token"}` (unauthenticated, Origin-checked, same limiter as login; an invalid token counts as a failure) → server: lookup `sha256(token)` with `expires_at > now`, delete the row (single use), create a session, 204 + cookie → `history.replaceState` strips the fragment → `location.replace('/')`. The token lives only in the fragment, so it never reaches proxy logs or Referer headers. If already logged in, `app.js` simply strips the fragment.
- iOS note (README): an installed home-screen app has its own cookie jar; log in once inside it (password or by opening the QR URL in Safari first, then adding to home screen from the logged-in tab).

### Rate limiting
- Per-IP, persisted: `login_attempts(ip, at)`; on `POST /api/login` and `POST /api/link/claim`, if `COUNT(*) WHERE ip=? AND at > now - LOGIN_WINDOW_MIN*60e3 >= LOGIN_MAX_FAILS` → `429` with `Retry-After` = seconds until the oldest counted attempt leaves the window. A failure inserts a row; a success deletes that IP's rows. Rows older than 24 h pruned by the sweeper. Survives restarts.
- Global, in-memory token bucket: capacity 30, refill 1 token / 2 s, consumed per attempt before scrypt; empty → `429 Retry-After: 2`. This slows distributed guessing without ever locking the owner out (no persisted global lockout, by design).
- Client IP: `req.socket.remoteAddress`; when `TRUST_PROXY=1`, the **rightmost** `X-Forwarded-For` entry (never the first - client-spoofable). Every login success/failure is logged with IP and label.

### CSRF posture
Three layers, no tokens:
1. `SameSite=Lax` - cross-site POST/PUT/DELETE/WS carries no cookie.
2. **Origin check** on every non-GET/HEAD request and on the WS upgrade: `originOk(req)` = `Origin` present AND (`new URL(origin).host === expectedHost` OR origin ∈ `ALLOWED_ORIGINS`), where `expectedHost = TRUST_PROXY ? (X-Forwarded-Host || Host) : Host`. If `Origin` is absent: allow only when `Sec-Fetch-Site` ∈ {`same-origin`, `none`}; otherwise `403 {"error":"bad_origin"}`. Browsers always send `Origin` on WebSocket upgrades, so the WS check is strict equality.
3. JSON routes require `Content-Type: application/json` (cross-origin forms cannot send that without a preflight the server never answers).

### WebSocket auth
`ws` runs with `noServer: true`. In `server.on('upgrade')`: path must be `/ws`; parse cookie → session lookup; `originOk`; only then `wss.handleUpgrade`. On failure write `HTTP/1.1 401 Unauthorized\r\nConnection: close\r\n\r\n` (or 403) and `socket.destroy()` - the handshake never completes, no first-message auth. Each socket stores `sidHash`; a 60 s timer re-checks every open socket's session row and closes with 4001 if gone (backstop; revoke/logout close immediately).

### Download auth
`GET|HEAD /f/:id/:name` and `/f/:id/thumb` require the session cookie. Unauthenticated: `302 /login` if `Accept` contains `text/html` (a tapped old link), else `401`. Ids are 16-char random but auth never relies on that. No public/capability links in v1.

### Headers
Every HTML/API response: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Cache-Control: no-store` (HTML + `/api/*`). HTML also gets:
```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' blob:; media-src 'self' blob:; connect-src 'self' ws://<host> wss://<host>; manifest-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'
```
(`<host>` = expectedHost of the request.) Consequence for the frontend: no inline `<script>`, no inline `style=""` attributes; set styles from JS via `el.style.prop = …` or classes. Unauthenticated `/api/*` → `401 {"error":"unauthorized"}`; the client redirects to `/login` on any 401.

## 5. Shared text sync protocol

### Model
One `Y.Doc` per side, `ytext = doc.getText('t')`, GC on (default). The server holds the authoritative persisted replica and relays; clients hold full replicas. There are **no version numbers**: the Yjs state vector (clientID → clock map) is the version, updates are idempotent and commutative, and concurrent inserts at the same index are ordered deterministically by clientID - both survive. Deleting already-deleted text is a no-op. A client that reconnects after hours sends `encodeStateAsUpdate(clientDoc, serverStateVector)` - exactly its unknown ops - so a stale tab can never overwrite anything.

Both sides import the same yjs version: server `import * as Y from 'yjs'`, browser `import * as Y from './vendor/yjs.js'`.

### Wire format (one WebSocket at `/ws`)
Binary frames = Yjs; first byte is a tag. Text frames = JSON control messages.

| Dir | Frame | Meaning |
|---|---|---|
| S→C | `{"t":"hello","proto":1,"now":<ms>,"limits":{"maxFileMB":2048,"ttlHours":168,"maxTextKB":2048,"storageMB":0},"peers":<n>}` | First message after upgrade. Client reloads once (guarded by `sessionStorage.protoReload`) if `proto !== 1`. `now` gives the client a clock-skew offset for countdowns. |
| S→C | binary `0x00 ‖ Y.encodeStateVector(serverDoc)` | Sent right after hello. |
| C→S | binary `0x01 ‖ Y.encodeStateAsUpdate(clientDoc, serverSV)` | Client's reply: everything the server lacks (may be an empty update - always sent). |
| C→S | binary `0x00 ‖ Y.encodeStateVector(clientDoc)` | Sent immediately after the above. |
| S→C | binary `0x01 ‖ Y.encodeStateAsUpdate(serverDoc, clientSV)` | Everything the client lacks. |
| S→C | `{"t":"synced"}` | Sent right after the frame above. Handshake complete. |
| C→S | binary `0x01 ‖ update` | Every local transaction (one per `input` event), no debounce. |
| S→C | `{"t":"ack"}` | Exactly one per `0x01` frame received from that client, sent after the update is applied **and persisted**. |
| S→C | binary `0x01 ‖ update` | Fan-out of another client's (server-merged) update. |
| S→C | `{"t":"files","files":[FileMeta…],"usedBytes":<n>}` | After hello and on every file change. |
| S→C | `{"t":"peers","n":<open sockets>}` | On connect/disconnect. |
| C→S / S→C | `{"t":"ping"}` / `{"t":"pong"}` | App-level heartbeat. |
| S→C | `{"t":"bye","reason":"revoked"\|"logout"\|"shutdown"}` then close | Codes: 4001 revoked/logout, 1001 shutdown, 4000 protocol error (malformed frame). |

`FileMeta = {"id","name","size","mime","createdAt","expiresAt"|null,"hasThumb"}`.

### Server state and handling (`lib/doc.js`, `lib/ws.js`)
- Boot: `for row of SELECT data FROM doc_updates ORDER BY seq: Y.applyUpdate(doc, row.data, 'load')`; if rows > 2000 or total bytes > 4 MB → compact. Only **then** attach `doc.on('update', onUpdate)`.
- `onUpdate(update, origin)`: `INSERT INTO doc_updates(data) VALUES(?)` (synchronous, `synchronous=FULL`, so it is on disk before this returns); `rows++`; if `rows > 2000` → compact in one transaction: `DELETE FROM doc_updates; INSERT … (Y.encodeStateAsUpdate(doc))`; broadcast `0x01‖update` to every socket except `origin`; schedule `text.txt` mirror (1 s debounce) and snapshot (30 s quiet, see below).
- On `0x01` from socket `ws`: `try { Y.applyUpdate(doc, payload, ws) } catch { send {t:"error"}; close(4000) }`, then `ws.send({t:"ack"})`. If the update contained nothing new, no `update` event fires (nothing persisted or broadcast) but the ack is still sent so the client's counter balances.
- On `0x00`: reply `0x01‖encodeStateAsUpdate(doc, sv)` then `{t:"synced"}`.
- The server never originates text edits. `ws` option `maxPayload: 4 * 1024 * 1024`.
- Persistence order guarantee: persisted → broadcast → ack. If the process dies between receipt and persist, the client still holds the update and the next handshake re-sends it.
- `text.txt` mirror: `DATA_DIR/text.txt.tmp` → `rename` → `text.txt`, debounced 1 s after the last change and on shutdown. If at boot `doc_updates` is empty but `text.txt` exists (hand restore), seed the doc from it.
- Shutdown: compact, write mirror, then close DB.

### Text history (server snapshots)
Table `snapshots(id, at, len, text)`. After each update, `clearTimeout(t); t = setTimeout(snapshot, 30000)`. `snapshot()`: `text = ytext.toString()`; skip if equal to the last snapshot's text; insert; delete rows beyond the newest 50; then delete oldest while `SUM(length(text)) > 20 MB`. `GET /api/history` → `[{id, at, len, preview:<first 80 chars, newlines→space>}]` newest first; `GET /api/history/:id` → `{id, at, text}`. Restore is client-side (below). The quiet period is `start({ snapshotQuietMs })`-overridable for tests.

### Client (`public/net.js`, `public/editor.js`, `public/app.js`)
State: `ws`, `synced` (bool), `sentStep2` (bool), `unacked` (int), `pendingRemote` (array of Uint8Array, used during IME composition), `status ∈ {connecting, live, saving, reconnecting, offline}`.

Boot (`app.js`):
1. `doc = new Y.Doc()`; `raw = localStorage.getItem('shelf.doc')`; if present `Y.applyUpdate(doc, fromBase64(raw), 'load')`. `textarea.value = ytext.toString()` (initial paint - the only direct `.value` write). Then attach the editor binding (§ below) and `doc.on('update', …)`.
2. `doc.on('update', (u, origin) => { persistLocal(); if (origin !== 'remote' && origin !== 'load' && ws?.readyState === 1 && sentStep2) { send(0x01, u); unacked++; renderStatus() } })`. `persistLocal` = 300 ms debounce → `localStorage.setItem('shelf.doc', toBase64(Y.encodeStateAsUpdate(doc)))` in try/catch. Edits made before `sentStep2` are captured by step 2's `encodeStateAsUpdate` at that moment; edits made while disconnected are captured by the next handshake.
3. `net.connect()`.

Handshake on every open: `unacked = 0; synced = false; sentStep2 = false`. On `hello` check proto. On `0x00`: `send(0x01, Y.encodeStateAsUpdate(doc, sv)); unacked++; send(0x00, Y.encodeStateVector(doc)); sentStep2 = true`. On `0x01`: `editor.composing ? pendingRemote.push(u) : Y.applyUpdate(doc, u, 'remote')`. On `ack`: `unacked--`. On `synced`: `synced = true`. Status: `live` when open ∧ synced ∧ unacked === 0; `saving` when open ∧ (¬synced ∨ unacked > 0); `reconnecting` when closed ∧ `navigator.onLine`; `offline` when closed ∧ `!navigator.onLine`.

Heartbeat: client sends `{t:"ping"}` every 20 s while `document.visibilityState === 'visible'`; if no frame of any kind arrives for 30 s → `ws.close()` and reconnect (catches half-open sockets after phone sleep; keeps nginx's 60 s `proxy_read_timeout` happy). Server: `ws.ping()` every 25 s, `terminate()` a socket that missed the previous pong.

Reconnect: on close (unless code 4001): backoff `min(10000, 500 * 2^n) ± 20 %` jitter; immediate attempt (reset backoff) on `online`, `pageshow`, `focus`, and `visibilitychange → visible`. On close code 4001: clear `localStorage` `shelf.*`, `location.replace('/login')`. Editing is always allowed regardless of status.

### Textarea binding (`editor.js`, pure parts in `textdiff.js`)
Invariant between events: `mirror === ytext.toString() === textarea.value` (except during composition, where remote updates are held at the network layer so the invariant still holds for the doc).

```js
// textdiff.js - pure
export function splice(oldS, newS, caret = newS.length) {
  const oldLen = oldS.length, newLen = newS.length, minLen = Math.min(oldLen, newLen);
  let p = 0; const pMax = Math.min(minLen, caret);
  while (p < pMax && oldS.charCodeAt(p) === newS.charCodeAt(p)) p++;
  let s = 0; const sMax = minLen - p;
  while (s < sMax && oldS.charCodeAt(oldLen - 1 - s) === newS.charCodeAt(newLen - 1 - s)) s++;
  const hi = c => c >= 0xd800 && c <= 0xdbff, lo = c => c >= 0xdc00 && c <= 0xdfff;
  if (p > 0 && hi(oldS.charCodeAt(p - 1))) p--;              // never split a surrogate pair
  if (s > 0 && lo(newS.charCodeAt(newLen - s))) s--;
  return { index: p, remove: oldLen - p - s, insert: newS.slice(p, newLen - s) };
}
// Shift a selection [s,e] across a Y.Text delta ({retain}|{insert:string}|{delete:n}).
export function shiftSelection(s, e, delta) {
  const collapsed = s === e; let pos = 0;
  for (const op of delta) {
    if (op.retain != null) { pos += op.retain; continue; }
    if (op.insert != null) {
      const n = op.insert.length;
      if (pos <= s) s += n;                                   // remote insert at the caret lands BEFORE it
      if (pos < e || (collapsed && pos <= e)) e += n;         // a selection's end does not swallow remote text
      pos += n; continue;
    }
    if (op.delete != null) {
      const n = op.delete;
      if (pos < s) s -= Math.min(n, s - pos);
      if (pos < e) e -= Math.min(n, e - pos);
    }
  }
  return [s, e];
}
```

```js
// editor.js - local → doc
ta.addEventListener('input', () => {
  if (ta.value.length > maxTextChars) { ta.value = mirror; toast('Text too large'); return; }
  const { index, remove, insert } = splice(mirror, ta.value, ta.selectionStart);
  if (!remove && !insert) return;
  doc.transact(() => { if (remove) ytext.delete(index, remove); if (insert) ytext.insert(index, insert); }, 'local');
  mirror = ta.value;
});
// doc → DOM (everything that did not come from this textarea: remote, 'ui', UndoManager)
ytext.observe((ev, tr) => {
  if (tr.origin === 'local') return;
  const focused = document.activeElement === ta;
  const [s, e] = shiftSelection(ta.selectionStart, ta.selectionEnd, ev.delta);
  const top = ta.scrollTop; let pos = 0;
  for (const op of ev.delta) {
    if (op.retain != null) pos += op.retain;
    else if (op.insert != null) { ta.setRangeText(op.insert, pos, pos, 'preserve'); pos += op.insert.length; }
    else if (op.delete != null) ta.setRangeText('', pos, pos + op.delete, 'preserve');
  }
  if (focused) ta.setSelectionRange(s, e);
  ta.scrollTop = top;
  mirror = ytext.toString();
  if (ta.value !== mirror) { console.warn('editor: resync'); ta.value = mirror; }   // divergence guard, should never fire
});
```
`setRangeText` does not fire `input`, does not reset scroll, and keeps the native undo stack coherent. The caret never moves except by the exact amount of remote text inserted/deleted before it. The other device's caret is never rendered.

**IME / composition:** `compositionstart → composing = true`; `compositionend → composing = false; setTimeout(flushPending, 0)` (lets a trailing `input` event fire first in browsers that order it after `compositionend`); `blur` also flushes. `flushPending()` applies each queued `0x01` payload with `Y.applyUpdate(doc, u, 'remote')` in order, which flows through the observer above with caret shifting. Local `input` events during composition still produce splices and are sent normally.

**Undo:** `undo = new Y.UndoManager(ytext, { trackedOrigins: new Set(['local', 'ui']), captureTimeout: 500 })`. Intercept `keydown` Ctrl/Cmd+Z (undo), Ctrl/Cmd+Shift+Z and Ctrl+Y (redo) and `beforeinput` with `inputType` `historyUndo`/`historyRedo` → `preventDefault()` → `undo.undo()/redo()`. After an undo/redo, place the caret at the end of the first insert in the resulting delta (or at the delete position). Undo never touches the other device's edits.

**Programmatic local edits use origin `'ui'`** (so they render via the observer and are undoable): Clear (`ytext.delete(0, ytext.length)`), Paste button (`ytext.insert(ta.selectionStart, text)`), share-inbox text and pasted-text-outside-the-box (`append('\n' + text)` - prefix `\n` only if the doc is non-empty and does not end with one), history Restore (`transact: delete all; insert snapshot`).

### Numbers
No send debounce (one frame per input event; ~30–60 bytes). `localStorage` persist 300 ms. `text.txt` 1 s. Snapshot 30 s quiet. URL chips 300 ms. Ping 20 s, dead-after 30 s, server ping 25 s. Backoff 500 ms → 10 s. Compaction at 2000 rows / 4 MB. Target visible latency: one RTT (LAN 5–40 ms, internet ~100 ms).

## 6. Files

### Endpoints
| Method & path | Auth | Purpose |
|---|---|---|
| `PUT /api/files?name=<enc>&type=<mime>` | cookie + Origin | Raw-body upload. `Content-Length` required (411). `> MAX_FILE_MB` → 413 before reading. `usedBytes + length > MAX_STORAGE_MB` → 507. Streams to `DATA_DIR/tmp/<id>` with a byte counter that destroys the request at declared length + 1 (400). On end: `fsync`, `rename` → `DATA_DIR/files/<id>`, `INSERT files`, broadcast `files`, respond `201 FileMeta`. Any error → unlink tmp. |
| `PUT /api/files/:id/thumb` | cookie + Origin | Body `image/jpeg` ≤ 200 KB → `DATA_DIR/files/<id>.thumb.jpg`, `has_thumb=1`, broadcast. 204. |
| `PATCH /api/files/:id` body `{"keep":true\|false}` | cookie + Origin | `keep:true` → `expires_at = NULL`; `keep:false` → `expires_at = now + TTL`. Broadcast. 200 FileMeta. |
| `DELETE /api/files/:id` | cookie + Origin | Delete now (unlink blob + thumb, ENOENT tolerated, then delete row). Broadcast. 204. |
| `GET /api/files` | cookie | `{files:[FileMeta…], usedBytes}` (curl/tests; the WS message is the normal path). |
| `GET\|HEAD /f/:id/:name[?dl=1]` | cookie | Download. `:name` is cosmetic; id must match `^[A-Za-z0-9_-]{16}$`. 404 if unknown **or `expires_at <= now`** (expiry exact to the second regardless of sweep timing). |
| `GET /f/:id/thumb` | cookie | The JPEG thumbnail, 404 if none. |
| `POST /share` / `GET /share` | - | Fallback when the SW is not controlling: `303 /` / `302 /`. |

Client uses `XMLHttpRequest` (`xhr.upload.onprogress` works everywhere incl. iOS Safari), `Content-Type` = `file.type || application/octet-stream`. `name` sanitised server-side: strip `/`, `\`, control chars, trim, cap 200 chars, default `file`. `type` must match `^[\w.+-]+\/[\w.+-]+$` else `application/octet-stream`. Original name lives only in the DB, never on disk.

### Storage layout (`DATA_DIR`, one volume)
```
/data/shelf.db (+ -wal, -shm)     all metadata, sessions, doc log, snapshots
/data/password.hash               only when auto-generated (0600)
/data/text.txt                    plain-text mirror of the box (tmp+rename)
/data/files/<id>                  blobs (no extension)
```

Same filesystem so `rename` is atomic. Do not put `/data` on NFS/SMB (SQLite).

### Schema (`lib/db.js`, run at boot; `PRAGMA journal_mode=WAL; synchronous=FULL; busy_timeout=5000`)
```sql
CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);           -- schema_version, pwfp
CREATE TABLE IF NOT EXISTS sessions (id_hash TEXT PRIMARY KEY, created_at INTEGER NOT NULL,
  last_seen_at INTEGER NOT NULL, ua TEXT NOT NULL DEFAULT '');
CREATE TABLE IF NOT EXISTS login_attempts (ip TEXT NOT NULL, at INTEGER NOT NULL);
CREATE INDEX IF NOT EXISTS login_attempts_ip ON login_attempts(ip, at);

CREATE TABLE IF NOT EXISTS doc_updates (seq INTEGER PRIMARY KEY AUTOINCREMENT, data BLOB NOT NULL);
CREATE TABLE IF NOT EXISTS snapshots (id INTEGER PRIMARY KEY AUTOINCREMENT, at INTEGER NOT NULL,
  len INTEGER NOT NULL, text TEXT NOT NULL);

  mime TEXT NOT NULL, created_at INTEGER NOT NULL, expires_at INTEGER, has_thumb INTEGER NOT NULL DEFAULT 0);

```
All timestamps are ms since epoch. `id = randomBytes(12).toString('base64url')` (16 chars). `meta.schema_version = '1'`; refuse to start on a newer value.

### TTL and the sweeper (`lib/files.js`)
`expires_at = created_at + FILE_TTL_HOURS*3600e3` (NULL when `FILE_TTL_HOURS=0` or kept). Sweeper runs at boot and every `SWEEP_INTERVAL_SEC` (timer `unref`'d): `SELECT id FROM files WHERE expires_at IS NOT NULL AND expires_at <= now` → for each: `unlink` blob and thumb (ENOENT tolerated) → `DELETE` row (unlink-first so a crash leaves a retryable row, never an invisible orphan) → if anything changed, broadcast `files` and log `sweep: removed N files (M bytes)`. The same tick prunes `login_attempts` > 24 h, expired `link_tokens`, and expired `sessions`. Boot reconcile: blobs in `files/` without a row → unlinked; rows without a blob → deleted; `tmp/*` → unlinked. "Delete" always means bytes gone from disk and row gone from the DB; there is no soft-delete.

### Download response
- `Content-Type` = stored mime; `Content-Length`; `Accept-Ranges: bytes`; single-range `Range` support (`206` + `Content-Range`, `416` when unsatisfiable); `HEAD` supported; `ETag: "<id>"`; `Cache-Control: private, max-age=86400`; `X-Content-Type-Options: nosniff`; `Cross-Origin-Resource-Policy: same-origin`.
- `Content-Disposition: inline` **only** for the positive allowlist `image/png, image/jpeg, image/gif, image/webp, image/avif, video/mp4, video/webm, video/quicktime, audio/*, application/pdf, text/plain`; everything else (including `image/svg+xml`, `text/html`, `image/heic`) is `attachment`. `?dl=1` forces `attachment`. Always `filename="<ascii fallback>"; filename*=UTF-8''<percent-encoded>`.
- `Content-Security-Policy: sandbox` on every file response **except `application/pdf`** (Chrome's PDF viewer does not render under `sandbox`; a PDF cannot script against the app origin). This is what makes an uploaded HTML/SVG inert on the app origin. README: do not strip response headers in the proxy.

### Broadcast
Every change (upload, thumb, keep, delete, sweep) broadcasts the **full list** `{t:"files", files:[…], usedBytes}` to every socket. Tens of files; deltas are not worth a bug.

### Phone and desktop intake (all funnel into `uploads.enqueue(File[])`)
- **Picker:** "Add files" button → `<input type="file" multiple>` (no `accept`: iOS offers Photo Library / Take Photo / Choose Files; iOS transcodes HEIC → JPEG for `image/*`-compatible picks from the library, which is what makes the file open on Windows). **Camera:** "Camera" button → `<input type="file" accept="image/*,video/*" capture="environment">`. Two inputs because `capture` changes the picker.
- **Clipboard paste:** `document.addEventListener('paste')`: if `clipboardData.files.length` → `preventDefault()`, enqueue (an unnamed/`image.png` blob is renamed `paste-YYYY-MM-DD-HH-mm-ss.png`); else if the textarea is not focused and there is text → append to the box (origin `'ui'`). Text pasted into the focused textarea is a normal splice. Never a base64 blob in the text. A "Paste" toolbar button uses `navigator.clipboard.readText()` (shown only when available - secure context) and inserts at the caret.
- **Drag-and-drop:** `dragenter/dragover/drop` on `document`; full-page dashed overlay while dragging; multi-file.
- **Share target (Android/Chrome, installed PWA over HTTPS):** `manifest.webmanifest` declares `share_target` (§
7). The OS POSTs multipart to `/share`; `sw.js` intercepts it entirely client-side, stores each file and the text/url in the Cache API bucket `share-inbox`, and responds `303 /?shared=1`. On every load of `index.html`, `app.js` drains the inbox (files → `enqueue` with real progress; text/url → appended on a new line) and deletes each entry. Because the page, not the SW, does the upload, it works even when the session had expired: the server 302s to `/login`, the user logs in, `/` loads, the inbox drains. Server never parses multipart. README states plainly: share target is Android/Chrome only and needs HTTPS + installed PWA; on iOS the paths are the picker, camera and paste.

### Upload queue UI (`uploads.js`)
Concurrency 2, FIFO. Each item renders instantly as a card in the file grid with name, size, `<progress>` (bytes/percent), MB/s, Cancel (aborts the XHR). Failure keeps the `File` object and shows a one-tap **Retry** plus a plain reason: `413` → "Too large (limit N MB)", `507` → "Storage full", `401` → "Logged out - reload", `0`/network → "Connection lost", other `4xx/5xx` with a non-JSON body → "Blocked by reverse proxy (body size limit?)". On `201`, if `file.type` starts with `image/`: `makeThumb(file)` → `createImageBitmap(file, { imageOrientation: 'from-image' })`, falling back to `<img src=objectURL>` + `img.decode()`; scale so the long edge is ≤ 320 px; `canvas.toBlob('image/jpeg', 0.7)`; `PUT /api/files/:id/thumb` if ≤ 200 KB. Undecodable images and non-images show a MIME icon. Text editing is never blocked by uploads; text and file transport fail independently.

### Service worker (`public/sw.js`) - share target only
```js
self.addEventListener('install', () => self.skipWaiting());
self.addEventListener('activate', e => e.waitUntil(self.clients.claim()));
self.addEventListener('fetch', event => {
  const url = new URL(event.request.url);
  if (event.request.method !== 'POST' || url.pathname !== '/share') return; // everything else: browser default, nothing cached
  event.respondWith((async () => {
    const fd = await event.request.formData();
    const cache = await caches.open('share-inbox');
    for (const f of fd.getAll('files')) {
      if (!(f instanceof File)) continue;
      await cache.put(new Request('/_inbox/' + crypto.randomUUID()), new Response(f, { headers: {
        'X-Kind': 'file', 'X-Name': encodeURIComponent(f.name || 'shared'), 'X-Type': f.type || 'application/octet-stream' } }));
    }
    const text = [fd.get('title'), fd.get('text'), fd.get('url')].filter(Boolean).join('\n');
    if (text) await cache.put(new Request('/_inbox/' + crypto.randomUUID()), new Response(text, { headers: { 'X-Kind': 'text' } }));
    return Response.redirect('/?shared=1', 303);
  })());
});
```
It does **not** cache `index.html`, JS, CSS, `/api/*`, `/ws`, or `/f/*` - a deploy is picked up on the next load, and the app never serves a stale client. `app.js` `drainInbox()` iterates `cache.keys()`, enqueues files / appends text, deletes each entry, and consumes `?shared=1` into a toast + `history.replaceState`.

## 10. Explicit non-goals for v1

- Multiple users, accounts, signup, invites, 2FA/TOTP, OAuth.
- Chunked/resumable uploads (single streaming PUT; Retry restarts from zero without re-picking the file). Metadata shape leaves room for it later.
- Public or capability share links for files; signed URLs.
- Server-side image processing (thumbnails are client-generated; HEIC arriving via Files gets an icon).
- Offline app shell / SW caching of any kind; the SW exists only for the share target.
- iOS share sheet integration (Web Share Target is Android/Chrome only).
- Rendering remote carets, "typing…" presence, or an awareness protocol (only a peer count).
- Markdown, rich text, syntax highlighting, multiple notes/tabs, folders.
- Content-hash dedupe of uploads; oldest-first eviction (only a hard quota).
- HTTP→HTTPS redirect inside the app (belongs in the proxy); the plain `http://LAN-IP` case must keep working.
- Horizontal scaling / more than one replica against the same volume (single process by design; document that a second instance must never share `DATA_DIR`).
- Per-session device naming (labels are UA-derived), telemetry, any runtime egress to third-party origins.
